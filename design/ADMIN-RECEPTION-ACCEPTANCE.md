# 栖愈管理后台接待改版验收记录

更新日期：2026-09-09

## 产品流程

后台以单门店、单日期为操作上下文，核心链路统一为：今日接待 → 预约详情 → 到店核销 → 开始服务 → 完成服务 → 结算。总部账号默认进入经营概览，门店账号默认进入今日接待；服务端继续执行角色、门店和技师数据权限。

- 今日接待：待到店、待服务、服务中、待结算均从完整筛选结果汇总，点击数字即可筛选。
- 预约管理：支持列表和日排期；日排期可按技师或房间查看，空白时段直接带入创建表单。
- 新建预约：手机号先查重，未命中时原位建档；项目、技师、房间、日期和时间联动并在提交前复验可约性。
- 统一详情：客户、项目、时间、资源、订单金额、实付金额、合法下一步与单笔操作记录集中在抽屉内。
- 到店核销：先输真实核销码并核对摘要，再确认到店；查询不改变状态，重复确认保持幂等，成功后可继续服务或接待下一位。
- 服务订单：按待服务、服务中、待结算、已完成处理，状态只能通过业务动作推进。

## 交互与视觉约束

- 鼠尾草绿作为主色，危险操作单独确认；表格、标签、抽屉和表单使用统一语义。
- 顶部门店、日期和搜索上下文在接待相关页面间保留，详情关闭后保留列表位置和筛选。
- 主操作触控高度不低于 44px；1024px 宽度下工具栏可换行，核心操作不依赖悬停。
- 反馈组件通过 `App.useApp()` 获取主题上下文；中文日期、分页、空态和按钮文案由 `zh_CN` 统一。
- 写操作均带加载锁；创建预约复用同一幂等键，失败时保留已识别客户和未提交表单。

## 接口范围

新增 `/admin/reception` 聚合接口，包含预约筛选和真实分页、完整结果状态汇总、详情、资源可约性、核销码解析与确认、业务动作、预约调整、客户查重与建档、单笔操作历史。预约编号仍为跨页面主键，原小程序接口保持兼容。

可约性统一检查门店营业时间、服务时长、准备与清洁占用、技师、房间和并发冲突；改期检查排除当前预约，最终写入再次校验。所有查询和写入权限均在服务端执行。
