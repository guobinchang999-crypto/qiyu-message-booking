# 栖愈管理后台 UI 设计规范

> 技术基线：Ant Design 5.29.3 + Pro Components 2.8.x  
> 核心用户：门店前台、店长、总部运营  
> 品牌语义：自然、克制、温暖、安静

## 信息架构

一级导航固定按“门店接待、门店资源、客户与会员、经营分析、系统管理”排列。门店前台围绕今天的接待任务工作，总部运营以跨店经营概览为入口。旧页面地址继续有效，菜单和操作同时受前端呈现权限与服务端权限约束。

## 页面骨架

- 页面标题说明当前任务，不复述菜单名称；标题右侧只放跨页面高频动作。
- 接待页顶栏依次为门店、日期、客户搜索、新建预约、到店核销。
- 筛选条件放在列表上方，列表操作只突出一个下一步，其他动作进入“更多”。
- 业务详情用右侧宽抽屉承接，使用户关闭后能回到原列表位置；简单确认用弹窗。
- 复杂表单按客户、项目与资源、时间、确认分区，不允许通过自由编辑状态推进业务。

## 组件语义

- 主色沿用鼠尾草绿；主按钮只用于当前页面最重要且可执行的动作。
- 成功、进行中、等待、异常和结束状态使用统一状态标签，不仅靠颜色传达含义。
- 订单金额与实付金额必须分开显示；时间同时显示服务时段，必要时补充准备和清洁占用。
- 空态说明“为什么为空”和可采取的动作；错误保留用户输入并提供重试入口。
- 使用 `App.useApp()` 调用消息和确认反馈，保证主题与中文上下文一致。

## 响应式与可访问性

- 电脑为主，验收宽度为 1920、1366 和 1024；1024 宽度时工具栏换行，表格允许横向滚动。
- 按钮、输入框和排期单元的核心触控目标至少 44px，不将重要操作仅放在悬停态。
- 核销码输入、检索、确认、继续服务和接待下一位支持连续键盘操作。
- 抽屉主操作固定在底部，滚动时不得被遮挡；加载状态阻止重复提交但保留关闭前的输入。

详细业务验收见 [管理后台接待改版验收记录](./ADMIN-RECEPTION-ACCEPTANCE.md)。

## 门店资源、客户中心与经营分析

- 资源详情保留当前列表上下文，门店关联资源复用专用页面；资料修改、启停和维护分开，影响未完成预约时展示数量与入口，服务端再次校验。
- 客户中心采用客户名单与会员资产双视图；入口取读取权限并集，内容与动作分别授权。客户和会员通过稳定 ID 关联，不依赖同名或脱敏手机号匹配。
- 余额调整留空金额并二次确认增减与预计余额；重试复用请求号，不能以关闭弹窗或重复点击新增流水。
- 优惠券按现有后端减免百分比换算中文折扣，例如减免 20% 显示 8 折；预览明确原价与优惠后金额。
- 经营概览与报表采用相同统计口径和日期范围。金额保留精度，趋势标注日期和元，汇总比例从原始总数计算；不能将订单金额称为现金实收。
- 主操作和输入控件使用 44px 高度，抽屉底部固定保存，错误保留输入；详情支持继续办理与返回。

本轮实现与未完成联调项见 [管理模块验收记录](./ADMIN-MANAGEMENT-ACCEPTANCE.md)。

## 系统管理

- 组织采用可搜索树与右侧详情布局；新增下级带入父组织，父级选择展示路径，改父级先核对影响人数。资料编辑与启停、删除分离。
- 菜单与字典归入高级配置。导航读取服务端持久化显示配置，并与已开发路由和实际权限取交集；加载失败展示重试，不恢复全部菜单。
- 菜单配置使用树形层级，目录、页面、按钮分型编辑。页面路由来自注册清单，内置页面的路由身份不可删除或替换；隐藏导航不撤销接口权限。
- 字典采用左侧类型、右侧分页选项布局。选项编辑抽屉只开放显示名称与排序，类型元数据不随单条选项保存被覆盖。当前未注册支持动态新增状态的业务，故不提供新增、删除及启停；服务器同样拒绝这些操作。
- 系统表单复用宽抽屉与固定保存区，保留失败输入、未保存确认和重复提交保护。组织树长名称单行省略，避免挤压层级与触控目标。

实施状态、截图及剩余项见 [系统管理验收记录](./ADMIN-SYSTEM-ACCEPTANCE.md)。
