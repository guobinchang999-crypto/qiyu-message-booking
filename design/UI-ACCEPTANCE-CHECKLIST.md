# 栖愈微信小程序 UI 验收清单

> 版本：1.0  
> 设计基准：[`UI-DESIGN-SYSTEM.md`](./UI-DESIGN-SYSTEM.md)  
> 开发提示词：[`CODEX-UI-DEVELOPMENT-PROMPT.md`](./CODEX-UI-DEVELOPMENT-PROMPT.md)

## 1. 验收规则

### 1.1 判定优先级

1. 可用性、安全区、可访问性和状态反馈；
2. `UI-DESIGN-SYSTEM.md` 中的设计令牌与组件规则；
3. 对应 `client-*-v2.png` 的内容结构和视觉构图；
4. TDesign MiniProgram 默认表现。

### 1.2 结论

- **通过**：P0/P1 为 0，页面关键项目全部满足，P2 有明确接受记录。
- **有条件通过**：P0 为 0，存在不阻断演示的 P1/P2，已明确修复负责人和时间。
- **不通过**：存在任意 P0，或核心页面/主操作/安全区未完成。

### 1.3 问题等级

| 等级 | 定义 | 示例 |
|---|---|---|
| P0 阻断 | 无法构建、页面不可达、关键数据丢失、核心主操作无效 | 无法登录进入演示、确认预约崩溃、签到重复创建记录 |
| P1 严重 | 主流程可继续但结果错误，或关键视觉/交互明显不可用 | 底栏点“订单”进入错误页面、固定按钮遮挡内容 |
| P2 一般 | 不影响主流程，但与规范有明显差异 | 卡片间距错误、缺少某个非关键空态 |
| P3 建议 | 细节优化 | 轻微字距、过渡动画节奏 |

- [ ] 没有把整张参考效果图作为页面背景或整页 Image。
- [ ] 所有新增文件和图层/组件使用语义化命名，无 `container1`、`group2`、`image3` 等名称。
- [ ] 设计令牌集中管理，页面没有大面积重复硬编码品牌色、字号和间距。

- [ ] 用户已有代码和无关改动未被覆盖。

## 3. 设计令牌验收

### 3.1 色彩

- [ ] 页面背景使用 `#F4F0EC` 或规范允许的表面色，不出现无依据的纯冷白大面积背景。
- [ ] 主操作统一使用品牌绿 `#3B533E`，按压态使用更深品牌色。
- [ ] 正文、辅助文字、占位符的层级清楚，正文对比度满足阅读要求。
- [ ] 暖金只用于会员、会员价和少量点缀，不承担主要操作。
- [ ] 成功、提醒、错误、禁用颜色语义一致，并同时提供文字/图标信息。
- [ ] 禁用控件不会看起来像可点击控件。
- [ ] Modal 遮罩与浮层层级正确，Toast 不被遮挡。

### 3.2 排版

- [ ] Logo 使用独立图片资源或明确占位，不使用普通文本冒充最终 Logo。
- [ ] 装饰性标题只用于页面标题、章节标题和结果标题。
- [ ] 正文、表单、数字使用系统无衬线，跨 iOS/Android 可读。
- [ ] 页面标题、章节标题、卡片标题、正文、说明和价格层级与规范一致。
- [ ] 最小正文不低于 22rpx；关键规则和价格不使用过小字号。
- [ ] 系统字体放大后，关键信息可换行且按钮不截字。
- [ ] 金额符号、整数、小数和单位基线对齐。

### 3.3 间距、圆角与阴影

- [ ] 页面水平边距为 32rpx，特殊全宽图片除外。
- [ ] 间距使用规范离散值，未出现大量 17rpx、29rpx 等随意数值。
- [ ] 同类卡片的内边距、列表间距和圆角一致。
- [ ] 普通卡片优先使用边框区分，没有重投影或多层阴影。
- [ ] 分隔线颜色和起始位置一致，不穿过头像/图片。

## 4. 响应式与安全区

对以下宽度分别截图和操作，不只缩放设计稿：

| 设备宽度 | 预期 |
|---:|---|
| 375px | 无横向溢出；按钮与价格不碰撞；日期/分类允许横向滚动 |
| 390px | 与效果图进行主要视觉对比 |
| 430px | 内容合理舒展，不出现过宽文本行或失控留白 |

- [ ] 自定义 Navbar 正确避让状态栏和微信胶囊按钮。
- [ ] 页面标题不会被返回按钮、通知、收藏或胶囊按钮遮挡。
- [ ] 底部操作栏和 TabBar 正确使用底部安全区。
- [ ] 滚动内容底部有足够占位，最后一行可以完整滚到固定栏上方。
- [ ] 横屏或不支持布局有明确限制，不出现无法返回的页面。
- [ ] 触控区域不小于 44px × 44px；底栏整项可点，不仅图标可点。
- [ ] 核心布局与390×822参考图误差目标不超过4px；允许因字体渲染产生小幅差异。
- [ ] 页面无横向滚动条、文字截断、组件重叠和图片拉伸。

## 5. 公共组件验收

### 5.1 Navbar 与 TabBar

- [ ] Navbar 返回行为正确，首页无多余返回按钮。
- [ ] 四个底栏入口固定为：首页、预约、订单、我的。
- [ ] 四项在所有相关页面的图标、文字、顺序和激活态一致。
- [ ] 点击底栏不会触发整张页面的其他默认跳转，不存在透明层点击穿透。
- [ ] 快速连续切换不会堆叠重复页面。

### 5.2 Button 与固定操作栏

- [ ] 每个视图最多一个实心主按钮。
- [ ] 主、次、文字、危险按钮层级明确。
- [ ] 按压态、禁用态、Loading 状态均可见。
- [ ] 写操作请求发出后按钮立即锁定，失败后恢复并提示。
- [ ] 固定操作栏不会遮挡正文、键盘或系统安全区。

### 5.3 Card、List 与 Tag

- [ ] 整卡可点击时有箭头或清晰提示。
- [ ] 卡内独立按钮不会同时触发整卡事件。
- [ ] 同类卡片的图片比例、标题行数、价格和动作位置一致。
- [ ] 标签最多显示3个，超出使用“+N”或折叠策略。
- [ ] 列表键值稳定，刷新后不会错位或闪烁。

### 5.4 Form、Modal 与反馈

- [ ] 手机号、验证码、人数等字段使用正确键盘类型。
- [ ] 必填、格式错误、字段错误和提交错误均有明确文案。
- [ ] 第一个错误字段可被定位，失败后保留用户输入。
- [ ] 验证码倒计时期间按钮禁用，倒计时结束可重新获取。
- [ ] Modal 的标题、对象、结果和按钮顺序清晰。
- [ ] Toast 仅用于轻量结果；可重试错误具有持久入口。

## 6. 通用状态验收

每个远程数据页面至少验证以下状态：

- [ ] **Skeleton**：结构接近真实内容，加载后无明显布局跳动。
- [ ] **Loading**：局部请求使用局部 Loading，避免无必要的全屏阻塞。
- [ ] **Empty**：有标题、解释和合理操作，不显示空白页面。
- [ ] **Error**：有错误说明和重试入口；表单内容不丢失。
- [ ] **Offline/Weak network**：说明网络问题，不伪装成空数据。
- [ ] **Disabled**：禁用原因可理解，控件不响应事件。
- [ ] **Duplicate submit**：登录、确认预约、支付、签到和评价不会重复触发。
- [ ] **Image failure**：显示统一占位，不破坏布局。

## 9. 核心演示链路

### 9.1 首次预约

- [ ] 登录 → 首页 → 门店/项目 → 服务详情 → 技师 → 时间 → 确认预约 → 预约成功 → 预约详情。
- [ ] 每一步返回后预约草稿仍保留。
- [ ] 修改门店/项目/技师/时间后，后续无效选择会被清理并提示，而不是静默保留冲突数据。

### 9.2 订单、签到与评价

- [ ] 首页/底栏 → 订单列表 → 预约详情 → 到店签到 → 成功反馈。
- [ ] 已完成订单 → 服务评价 → 提交成功 → 订单列表/详情显示已评价。
- [ ] 再次预约可以带入门店和项目，但不直接复用过期时间。

### 9.3 底部导航

- [ ] 首页 → 预约。
- [ ] 首页 → 订单。
- [ ] 首页 → 我的。
- [ ] 预约/订单/我的 → 首页。
- [ ] 快速连续点击不会错跳、闪屏或重复入栈。

## 10. 可访问性、隐私与文案

- [ ] 图标按钮具有可访问名称，纯装饰图不重复朗读。

- [ ] 手机号、用户信息和预约码按场景脱敏或限制展示。
- [ ] 用户协议、隐私政策、评价规范等链接有真实占位路由，不是无响应文字。
- [ ] 全站术语统一：门店、服务项目、技师、预约、到店、签到、评价。
- [ ] 全站没有门店经营类型或门店独立权益提示。
